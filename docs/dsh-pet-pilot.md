# dsh-pet 真实表现底座迁移

## 当前状态

**本机迁移已完成：云岚继续使用原有成长、记忆、人格、反馈与权限核心，桌面形象改由固定提交的 dsh-pet 渲染器显示。** 旧的 Qt 形象窗口不再显示，但核心进程、原生对话/成长卡/语音与云端设置窗口、审计和授权逻辑都保留；表现端只负责画宠物、气泡和动作。

- 固定上游提交 **`3c99b1bb4d1bcb831880e8871718c50b64af0d9b`**，不是 npm 上同版本号 `0.4.1` 的产物。npm 包的 `gitHead` 为 `51c3395d…`，落后 13 个提交，包含播放链、拖拽初始偏移和 IME 等差异，因此没有直接安装。
- 运行时从官方源码按 Git blob 逐个校验重建：**301 个上游文件、65,531,961 字节**；共享核心由固定源码用 esbuild 重新生成（170,716 字节），没有复用 npm 的旧 `shared-core.js`。
- 表现宿主是**受限 Electron 主进程**，只实现渲染器需要的 `/config`、`/state`、素材与播放回执；没有 HTTP 监听、聊天/余额/待办/云端接口，也没有截屏、麦克风、下载或任意导航能力。
- 核心与表现宿主之间是**父子进程**：核心持有子进程，Windows 下用随机命名管道 + 256 位一次性握手密钥传输控制消息；子进程只通过 stdout 回传白名单事件。没有 TCP 端口，也没有无鉴权的本地 API。
- 核心继续作为唯一写入者：`growth.json`、`memory.json`、`personality.json`、`continuity.json` 等存档格式与路径均未改变。表现端不生成记忆、不训练动作、不调用云模型。
- 旧动作模拟在外部表现模式下关闭：`run/hop/spin` 只发送**动作意图**，不会伪造落地/疲劳/学习结果，也不会把渲染回执当作训练样本。点击/摸头只转发语义位置，由核心自己的 `BehaviorLearner` 记录。

### 本机实测结果

- 真实核心 + 真实 Electron 窗口端到端：核心 `ready`、`SUCCESS` 状态气泡“完成啦”、工作状态动画实际解码播放（视频 `readyState=4`、时间推进）。
- 隐藏/显示链路：渲染端菜单命令 → 核心 → 宿主 `hide`/`show` → 状态回传，窗口实际隐藏并恢复。
- 实机切换：安装后旧 helper 退出，新 helper（PID 变化）拉起独立 Electron，桌面只保留一个 `dsh-pet 桌宠（桌面模式）` 窗口（720×640，置顶）；旧 `DSH 云岚 · 成长版` 窗口不再出现。
- 实机交互：对窗口命中区做一次真实鼠标点击后，`behavior.json` 的 `pets`/`headPats` 增加并写入 `pet1` 发现记录；渲染端只发送 `interact-head`/`interact-poke` 语义命令，没有把像素坐标或原文上传。
- 动作完整迁移：右键“动作”树包含待机、转向、拖拽、点击回应、移动、随机分类与事件动画共 **109 段 WebM**，可逐项点播；随机动作链、拖拽抛掷、点击回应和朝向翻转也保留。第一项“云岚菜单…”仍进入原生对话/成长/设置菜单。
- 睡觉/起来：右键第二项按状态显示“睡觉”或“起来”，播放 `睡觉-开始 → 睡觉-循环 → 睡觉-起来` 三段；睡眠状态写入表现端 `user-data/sleep.json`，重启后恢复。托盘也提供“让云岚睡觉/叫醒云岚”。睡着时核心状态气泡与动作暂停显示，醒来后恢复。
- 失败恢复：强杀 Electron 主进程后，核心检测到控制管道断开、关闭语音并退出；DSH 宿主在约 12 秒内重启 helper 与新的 Electron 窗口，未留下孤儿进程或双实例。

### 启用与回滚

安装脚本在备份原 helper 后写入显式激活文件 `~/.dsh/yunlan-renderer/active.json`，并只重启桌宠进程，不重启 DSH：

```powershell
# 安装（会先备份原 helper）

# 回滚到旧 Qt 形象
```

激活文件缺省不存在；缺失、格式错误或路径无效时核心**失败关闭**（不会悄悄退回旧形象），需要回滚时删除/停用该文件并恢复备份二进制。表现宿主崩溃时核心会关闭语音与动作并报告断开，不会留下无控制方的动画进程。

- 外部模式下只转发“头部/戳一下”两种语义点击；旧 Qt 的尾巴/脸颊细分与像素命中不再参与学习，避免把渲染坐标伪造为原精灵命中。

## 请求范围与隐私

只使用这些端点：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/lock` | 取锁或以同一 ID 续期 |
| POST | `/broadcast` | 固定合成文本气泡，`anim:false` |
| POST | `/anim` | 可信映射中的池内动画名字 |
| GET | `/playback/<id>` | 读取该次动作的渲染端回执 |
| POST | `/bubble/clear` | 持有自己的锁时请求清空说话气泡 |
| POST | `/lock/release` | 只释放自己的锁，绝不 `force` |

不调用 `/chat`、`/whisper`、余额、音频、历史、配置写入、位置、抛掷、关闭宿主、模型清单或播放回执上报接口；不发起模型生成，也不把 mock 回执写入真实服务。

- 目标地址必须严格写为 `http://127.0.0.1:端口`，没有默认端口、端口扫描、DNS 名字、用户名密码、路径、查询或重定向跟随。
- 使用 Node 原生 HTTP 直连数字回环地址，不读取代理环境变量，不携带浏览器 Cookie 或 Authorization。
- 响应有大小、MIME 和时间预算；HTTP 200 下的 `ok:false` 同样是失败；不自动重试动作。
- 不输出上游错误原文、锁 ID、播放 ID、地址或文本；结果只含固定枚举、是否受理和清理结果。
- `syntheticOnly:true` 不是“已鉴权”。上游 API 自身无鉴权的风险仍存在，本模块没有把整个上游服务变安全。

### 为何固定 `surface=both`

上游 `/broadcast` 在指定 `web` 或 `desktop` 时会写入 `voiceTo`，可能让显示端合成在线语音。`both` 不写这个目标，因此当前气泡只投喂文本，且 `anim:false` 不触发隐式说话动画。

这要求**独立测试角色的 `display=both`**；`both` 是配置资格检查，不是定向路由，不能保证只有一端显示。它不关闭上游其他自动功能。真实试点前必须在隔离配置里明确关闭自动碎碎念、余额、梦话、工作联动及语音，避免第二个决策中心。适配器不会为了做到这些而擅自改写用户配置。

## 执行、取消与失败

1. 一个适配器同一时刻只接受一次场景；第二次请求立即 `busy`，不积压队列。
2. 取得短租约后投喂气泡，可选点播指定动画。
3. 观察期间以同一锁 ID 续期检测接管；不抢锁、不自动重新取锁。
4. 动画只有回执为 `ended` 才标记 `renderer-reported-ended`。`accepted`、`playing` 观察到期均是 `playback-unconfirmed`，不是成功播放。
5. `failed`、`cancelled`、未知或不匹配的回执均不能当作动作成功，更不增加 XP 或训练样本。
6. 收尾使用独立的有限清理预算，即使原请求已取消也尝试清空气泡和释放自己的锁。清理失败如实报告。

**取消不是停止动画的证明：**

- `cancel()` / AbortSignal 会停止本地后续演出请求，并中止挂起的读取。
- `/bubble/clear` 只撤回说话气泡；不会停动画、位移或抛掷。
- `/lock/release` 只放弃控制；不会停动画或清空气泡。
- 上游没有本阶段可以依赖的通用动画停止接口，所以报告始终保留 `animationStopConfirmed:false`。
- 用户接管后，旧锁的清理可能被拒绝。不会为了“清理成功”去 `force`、去掉锁参数或抢新锁覆盖用户行为。
- 请求超时或取消可能发生在宿主已执行之后，不能保证撤回已到达上游的动作。若取锁响应不明，适配器进入租约冷却，避免马上重复取锁；这是本地保守限制，不是服务端事务回滚，也不能证明延迟处理的宿主绝不会在冷却后才建立锁。
- 不依赖“新动画覆盖旧动画就代表旧动画已取消”。本阶段不写播放回执，不用伪造 `cancelled` 来冒充媒体停止。
- 动画名字通过白名单不等于素材文件存在；缺失素材仍可能导致播放失败。
- 取锁会唤醒上游睡眠宠物。因此只允许独立测试角色，拒绝默认 `main`。
